Shut the PC down safely before the battery runs out, without writing a script.

**Battery low**

- A new event, **Battery low**, fires once per outage when the UPS is on battery and the
  charge falls to 20 % or the estimated time left to 10 minutes. Change either limit, or
  turn it off with 0, in Configuration → Events. The time left has to be low in two
  readings in a row, so a short load spike doesn't count. Unlike *Grid lost*, it also
  fires when UPS Tools starts on a battery that is already low.
- **Unreachable on battery** (Configuration → Events, off by default): if the UPS stops
  answering while on battery, *Battery low* fires after that many minutes, since its
  charge can't be known any more.
- **Changed behaviour:** *Grid restored* now stops the *Battery low* scripts that haven't
  started yet, as well as the *Grid lost* ones.
- After updating, you get a *Battery low* notification at 20 % / 10 minutes even if you
  attach no scripts to it. Turn the notification off in Configuration if you don't want it.

**Sleep, Hibernate and Shut down**

*Add action* on any event adds one of these to its list, next to your scripts. A window on
top of everything counts down first (60 s by default, up to 10 minutes) with *Cancel* and
*… now*; with nobody at the PC, it runs out and the action goes ahead. Cancelling skips the
scripts after it. If the grid comes back during the countdown, the window closes and
nothing happens. *Shut down* closes apps even if they have unsaved work.

**Scripts**

- Scripts now get the event and the UPS's state in environment variables: `UPS_EVENT`,
  `UPS_GRID`, `UPS_BATTERY_PERCENT`, `UPS_RUNTIME_MINUTES`, `UPS_LOAD_W`,
  `UPS_OUTAGE_SECONDS` and more (see the README). Scripts that run as administrator get
  them too.
- A script set to *Wait until it finishes* can have a time limit (*at most … min*). If it is
  still running by then, the next script starts anyway, so a script that hangs can't keep a
  later *Hibernate* from happening. 0, the default, waits as long as it takes.

**Grid lost**

**Wait before "Grid lost"** (Configuration → Events, off by default): the grid must stay
gone this long before *Grid lost* fires, so a short flicker runs no scripts and is only
logged.

Nothing changes for the Bluetooth connection. Existing settings and scripts carry over as
they are.
